# ✝️ 샘뜰 카페 (봉원교회 카페) 포스

Next.js + Tailwind CSS + Supabase로 만든 카페 **포스(POS)** 시스템입니다.
손님이 직접 주문하는 페이지는 없애고, 카운터에서 관리자 계정 하나로 주문을 받고
매출을 기록합니다.

- 주소로 접속하면(`/`) 바로 포스 로그인(`/admin`)으로 넘어갑니다.
- 로그인 후 탭 네 개로 운영합니다:
  - **주문받기** — 휴대폰 화면 기준으로 만든 터치 포스. 메뉴 타일을 눌러 주문서를 만들고
    `계좌이체` 또는 `현금`을 누르면 그 자리에서 결제 완료 처리되어 매출로 기록됩니다.
    - HOT/ICE는 타일 안의 버튼으로 한 번에 선택
    - 자주 나가는 메뉴는 **⭐ 자주 쓰는** 칩에 모아서 첫 화면에 표시 (메뉴 탭에서 ⭐ 토글)
    - **텀블러 할인은 항목별**입니다. 주문서의 각 줄에 있는 🥤를 누른 음료만 500원 할인
    - 이름은 비워두면 `3번`처럼 그날 순번으로 저장
    - 주문서는 화면 아래 시트로 붙어 있고, 담긴 게 없으면 자동으로 접혀 메뉴가 넓게 보입니다
  - **주문내역** — 날짜별 주문 목록. 건수·매출·계좌이체/현금·텀블러 할인을 위에
    요약하고, **매출 요약 복사** 버튼으로 장부에 옮겨 적을 수 있습니다.
    잘못 찍은 주문 삭제와 완료 ↔ 대기 전환도 여기서 합니다.
    지난 내역은 날짜를 눌러 달력에서 고르거나, 매출 탭 달력에서 날짜를 고른 뒤
    "이 날 주문내역 보기"로 바로 넘어갈 수 있습니다. 포스 도입 전 주문도 같은
    테이블에 그대로 남아 있어 함께 조회·집계됩니다.
  - **매출** — 달력에서 날짜를 골라 하루 매출·주문 수·평균·결제수단별·메뉴별 판매 확인
    (달력 칸에 일별 매출 표시, 월 합계 제공)
  - **메뉴** — 메뉴 추가/수정/삭제, 품절 토글 (수정 즉시 주문받기 화면에 반영)

배포 주소: https://seamtteul-cafe.vercel.app (main 브랜치에 push하면 Vercel이 자동 재배포)

---

## 1. 처음 실행하기

```bash
npm install
npm run dev
```

http://localhost:3000 접속. **Supabase 설정 전에도 화면은 뜨지만**(내장 예비 메뉴 표시),
주문 저장/조회와 메뉴 관리는 아래 설정을 마쳐야 동작합니다.

## 2. Supabase 연결 (5분)

1. https://supabase.com 에서 무료 프로젝트를 만듭니다.
2. 대시보드 왼쪽 **SQL Editor** 에 `supabase/schema.sql` 파일 내용을 붙여넣고 **Run** 합니다.
   (orders/menu_items 테이블 + 접근 정책 + 기본 메뉴 시드 + 실시간 설정이 한 번에 생성됩니다)
   - **이미 예전 버전을 쓰고 있었다면 이 파일을 한 번 더 Run 해 주세요.** 포스에서 쓰는
     `payment_method`(결제수단), `discount`(할인), `is_favorite`(즐겨찾기) 컬럼이
     추가됩니다. 여러 번 실행해도 안전하게 만들어 두었습니다.
3. 대시보드 **Project Settings > API** 에서 두 값을 복사합니다:
   - `Project URL`
   - `anon public` (publishable) 키
4. 프로젝트 루트의 `.env.local.example`을 복사해 `.env.local` 파일을 만들고 값을 채웁니다:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://xxxxxxxxxxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=발급받은_키
ADMIN_PASSWORD=abc123
```

5. dev 서버를 재시작합니다 (`Ctrl+C` 후 `npm run dev`).

## 3. 메뉴 수정하는 법

**포스 > 메뉴 탭**에서 추가/수정/삭제/품절/⭐즐겨찾기 처리를 하면 됩니다.
코드 수정이나 재배포 없이 즉시 주문받기 화면에 반영됩니다.

`src/data/menu.ts`의 `FALLBACK_MENU`는 Supabase에 연결하지 못했을 때만 쓰이는
예비 메뉴이므로 평소에는 손댈 필요가 없습니다.

## 4. 로그인

- 주소: `/admin` · 비밀번호: `ADMIN_PASSWORD` 환경변수 값 (설정하지 않으면 **abc123**)
- 비밀번호 검증은 서버 API(`/api/admin/login`)에서 하고, 성공 시 httpOnly 세션 쿠키(7일)가
  발급됩니다. 비밀번호는 브라우저에 노출되지 않습니다.
- 태블릿 한 대로 쓰면 한 번 로그인해 두고 계속 쓰면 됩니다. 기기를 두 대 이상 쓰면
  Supabase Realtime으로 주문내역이 서로 동기화됩니다.

> ⚠️ 남은 보안 한계: 주문/메뉴 데이터의 읽기·쓰기는 여전히 공개 anon 키 + RLS 정책으로
> 이루어집니다. 교회 내부용으로는 충분하지만, 외부에 완전히 공개할 서비스라면
> 데이터 작업도 서버 API로 옮기거나 Supabase Auth 기반으로 정책을 좁히세요.

## 5. 색·로고

로고(`public/logo.webp`)에서 뽑은 색을 `src/app/globals.css`의 `@theme`에
토큰으로 정의해 두었습니다. 화면에서 `bg-blue-500` 같은 기본 색을 쓰지 말고
아래 토큰을 쓰세요.

| 토큰 | 색 | 쓰는 곳 |
|---|---|---|
| `cream` | `#FEFDF9` | 페이지 배경 (로고 배경과 같은 값이라 로고가 자연스럽게 얹힙니다) |
| `paper` | `#FFFFFF` | 카드 |
| `forest` | `#435332` | 기본색 — 주요 버튼, 활성 탭/칩, 계좌이체 |
| `sun` | `#E2A944` | 강조 — HOT, 즐겨찾기 ⭐, 대기 상태 |
| `brown` | `#715F4D` | 보조 — 현금, 요약 복사 |
| `ice` | `#4E767E` | ICE |
| `clay` | `#B4452F` | 삭제·경고 |
| `ink` / `ink-soft` / `ink-faint` / `line` | | 글자·구분선 |

파비콘(`src/app/icon.png`)은 로고의 해 부분을 잘라 만들었습니다.

## 6. 금액·계좌 정보 바꾸기

텀블러 할인 금액과 계좌이체 안내 문구는 `src/lib/config.ts` 한 곳에 모여 있습니다.

## 7. 휴대폰에서 쓰기

카운터에서 휴대폰으로 쓰는 것을 기준으로 맞춰 두었습니다.

- **홈 화면에 추가**하면 주소창 없이 앱처럼 열립니다 (`manifest.ts`, `display: standalone`).
  아이폰은 Safari 공유 → "홈 화면에 추가", 안드로이드는 Chrome 메뉴 → "앱 설치".
- 누르는 것은 모두 **44px 이상**입니다.
- 입력칸 글자를 16px로 고정해 iOS에서 **누를 때 화면이 확대되지 않습니다**.
- `touch-action: manipulation`으로 더블탭 확대와 탭 지연을 없앴습니다.
- 주문 받는 동안 **화면이 꺼지지 않습니다** (`useKeepAwake`, 지원 기기에 한함).
- **인터넷이 끊기면** 화면 위에 바로 알리고, 결제 버튼을 눌러도 저장을 시도하지 않습니다.
- 결제 버튼은 ref로 잠가 **연타해도 두 번 저장되지 않습니다**.
- 화면이 깨져도 `admin/error.tsx`가 받아 "다시 시도"로 복구됩니다.
- Realtime이 막혀도 오늘 주문은 20초 안에 갱신됩니다 (화면이 켜져 있을 때만).

## 8. DB 설정이 덜 끝났을 때

필요한 컬럼이 없으면 포스를 열 때 **화면 맨 위에 빨간 경고 배너**가 뜹니다.
(2026년 8~10월에 `schema.sql`을 실행하지 않은 채로 7주간 운영되어
결제수단·할인이 컬럼에 저장되지 못한 일이 있었습니다. 그때는 경고가 결제 직후
접히는 영역 안에 있어서 아무도 보지 못했습니다.)

그 기간 데이터는 `supabase/recover-2026-10.sql`로 복구했습니다 — 메모에 남은
`결제: 현금` / `결제: 계좌이체` 문구를 컬럼으로 되살리는 1회성 스크립트입니다.

## 9. 나중에 전용 포스기로 옮긴다면

계산 규칙은 화면과 분리해 `src/lib/`에만 두었습니다. 다른 환경으로 옮길 때
이 파일들만 가져가면 됩니다. 새 기능을 넣을 때도 계산은 먼저 `src/lib/`에
순수 함수로 쓰고, 컴포넌트는 그 결과만 그리게 유지하세요.

| 파일 | 담은 규칙 |
|---|---|
| `config.ts` | 텀블러 할인 금액, 계좌 정보 |
| `types.ts` | 주문/결제수단 타입, 항목 합계, 텀블러 잔 수 |
| `sales.ts` | 하루 매출 집계, 메뉴별 판매, 요약 텍스트 |
| `orders.ts` | 주문 저장, 주문번호 매기기 |
| `date.ts` | 로컬 기준 하루 경계 |
| `schema.ts` | 필요한 컬럼 존재 확인 |

## 폴더 구조

```
src/
  app/
    page.tsx            # 루트(/) → /admin 으로 이동
    admin/page.tsx      # 로그인 + 포스 셸 (탭 전환)
    api/admin/          # 관리자 로그인/세션 API (서버 측 인증)
    layout.tsx          # 공통 레이아웃/메타데이터
    globals.css         # 색 토큰(@theme) + 전역 스타일 (밝은 테마 고정)
    icon.png            # 파비콘 (로고의 해)
    apple-icon.png      # iOS 홈 화면 아이콘
    manifest.ts         # 홈 화면에 추가(PWA) 설정
    admin/error.tsx     # 포스 화면 오류 안전망
  components/admin/
    PosTab.tsx          # 주문받기 (메뉴 버튼판 + 주문서 + 결제)
    OrdersTab.tsx       # 주문내역 (날짜별 목록/요약/삭제)
    SalesTab.tsx        # 매출 (달력 + 일별 상세)
    MenuTab.tsx         # 메뉴 관리
  data/
    menu.ts             # 메뉴 타입 + 예비(폴백) 메뉴
  components/
    useKeepAwake.ts     # 주문 받는 동안 화면 꺼짐 방지
    useOnline.ts        # 인터넷 끊김 감지
  lib/                  # 화면과 무관한 계산 규칙 (전용 포스기로 옮길 때 이 폴더만)
    config.ts           # 할인 금액·계좌 정보
    date.ts             # 하루 단위 날짜 유틸
    sales.ts            # 매출 집계 (주문내역/매출 탭 공용)
    orders.ts           # 주문 저장 + 주문번호 매기기
    schema.ts           # 필요한 컬럼 존재 확인
    supabase.ts         # Supabase 클라이언트
    menu.ts             # 메뉴 불러오기 (DB 우선, 실패 시 폴백)
    types.ts            # 주문/결제수단 타입, 포맷 함수
    adminAuth.ts        # 관리자 세션 토큰 (서버 전용)
public/
  logo.webp             # 로고 (로그인 화면·헤더)
  icon-192.png / icon-512.png / icon-maskable-512.png   # 홈 화면 아이콘
supabase/
  schema.sql            # DB 테이블/정책/시드 SQL (Supabase SQL Editor에서 실행)
  recover-2026-10.sql   # 밀린 마이그레이션 + 메모에서 결제수단 복구 (1회성)
```
